# 5. Optimization and Training Pipeline

MrMustard features a built-in Riemannian optimization engine (`mrmustard.training`). Because optimizing quantum circuits involves constrained geometry (e.g., Symplectic matrices, Unitary matrices), standard gradient descent is insufficient.

This document details how parameters are marked for training, how the JAX backend computes gradients, and how the `Optimizer` applies Riemannian metric updates.

## 1. Parameters and Variables

In MrMustard, parameters defining states and gates (like `alpha`, `r`, `phi`, `symplectic`) are instantiated via the `mrmustard.parameters` module.
- A standard parameter is `Constant`.
- If an optimization is needed, a parameter is defined as a `Variable` with `trainable=True`.

```python
from mrmustard.parameters import Variable

# Define a trainable squeezing magnitude, bounded between 0 and 1
r_val = Variable(0.5, name="r", bounds=(0.0, 1.0))
```

## 2. The Cost Function and Autodiff

To train a circuit, a user writes a standard Python function (the `cost_fn`) that accepts the trainable parameters and returns a scalar loss.

```python
def cost_fn(r_val):
    state = Vacuum(0) >> Sgate(r=r_val)
    target = DisplacedSqueezed(r=0.9)
    return 1 - state.fidelity(target)
```

### JAX Trace
To optimize this, MrMustard **must** be using the `jax` backend.
The `Optimizer.minimize()` function collects all parameters and calls `math.value_and_gradients(cost_fn, parameters)`.

In `backend_jax.py`, this maps to:
```python
def value_and_gradients(self, cost_fn, parameters):
    # This uses jax.value_and_grad to trace the execution of the cost function
    # against the variables marked as trainable.
    loss, grads = jax.value_and_grad(cost_fn)(parameters)
    return loss, grads
```

The JAX XLA compiler traces the entire pipeline:
1. `Sgate` generation.
2. Tensor contractions (`complex_gaussian_integral_2`).
3. Fidelity calculation.
It computes the exact analytical gradients for all operations in reverse mode.

## 3. The `Optimizer` and Riemannian Updates

Once the backend returns the raw Euclidean gradients, the `Optimizer` class (in `mrmustard/training/optimizer.py`) applies the updates.

However, if a parameter is constrained to a manifold (e.g., a full `Symplectic` matrix gate), applying a Euclidean gradient update ($S = S - \alpha \nabla S$) will immediately pull the matrix off the Symplectic manifold, destroying the physical validity of the quantum gate.

### `ParameterUpdate`
The `Optimizer` uses the `parameter_update` module. For every parameter, it checks its geometric type (Euclidean, Symplectic, Unitary, Orthogonal).

If the parameter is Symplectic:
1. The `Optimizer` calls `math.euclidean_to_symplectic(S, grad_S)`.
2. The backend computes the Riemannian gradient $Z_S = \frac{1}{2}(Z + J Z^T J)$ where $Z = S^T \cdot \text{grad}_S$.
3. The `Optimizer` then performs a **Retraction** to update the variable while staying on the manifold. For Symplectic manifolds, the update rule often involves matrix exponentials or Cayley transforms generated by the Riemannian gradient.

### Adaptive Learning Rates
The `Optimizer` supports specific learning rates for specific manifolds (e.g., `symplectic_lr`, `euclidean_lr`). It applies the parameter updates iteratively until the `cost_fn` converges or the maximum number of steps is reached.
